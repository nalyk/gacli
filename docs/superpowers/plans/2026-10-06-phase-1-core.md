# Phase 1 — Core (operation catalogue, output & exit contract) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Introduce the operation catalogue (`defineOperation`), the CLI adapter that mounts it onto commander, the agent-aware output/exit-code contract and `gacli schema`, and prove it end-to-end by migrating `report run`, `metadata get` and `admin custom-dimensions *`.

**Architecture:** `src/core/` holds pure, testable modules: errors, agent detection, rendering, the operation type, and the adapter. Operations live in `src/operations/**` and call the existing service layer (data) or the typed admin client directly. Hand-written commands (`config`, `auth`, `explore`, `mcp`, `skills`, and from this phase `schema`) keep using `resolveGlobalOptions` + `handleError`, which now route through the new error and format contract.

**Tech Stack:** Node ≥22.12, TypeScript 6, commander 15, zod 4, vitest 4, biome 2.4, @modelcontextprotocol/sdk v1 (v2 arrives in phase 3).

**Spec:** `docs/superpowers/specs/2026-10-05-gacli-modernization-design.md` (§5.1–5.4, §5.9 schema/agent help, §7, §6 row 1)

## Global Constraints

- Branch: `feat/phase-1-core` off `next`, merged back into `next`. Never `main`.
- Commits: conventional style with **no AI attribution** (user memory). The first commit that changes a contract carries a `BREAKING CHANGE:` footer, since this line is 2.0.0.
- Every existing command name and every existing flag string keeps working. New flags may be added.
- Exit codes (spec §5.4): `0` ok · `1` api/internal · `2` usage/validation · `3` auth · `4` confirmation required · `5` not found · `6` quota.
- Default format: explicit `-f`, then `GACLI_FORMAT` env, then config `format`, then auto. Auto is `table` when stdout is a TTY and no agent or CI is detected, otherwise `json`.
- Agent env vars: `CLAUDECODE`, `CODEX_THREAD_ID`, `CURSOR_AGENT`, `AI_AGENT`, `GACLI_AGENT`. CI: `CI`.
- JSON is pretty-printed when stdout is a TTY and compact otherwise.
- Imports end in `.js`. Only `handleError` (CLI edge) calls `process.exit`, apart from the existing `auth/login.ts` and `skills/install.ts` paths.

## Review Focus

1. A piped `gacli report run … | jq` with no `-f` must yield parseable compact JSON with no spinner bytes on stdout (Task 3/5).
2. A delete-category op (`admin custom-dimensions archive`) in a non-TTY without `--yes` must exit 4 and print the re-run command, and must not call the API (Task 5).
3. Unknown flag / missing required option / non-numeric `--limit` must exit 2. With `-f json`, stderr is a single JSON error line (Task 2/5).
4. `gacli report run --help` must still list every flag string it listed in 1.x (Task 1 fixture, Task 6).
5. `--fields` naming a field absent from every result row must exit 2, not print empty columns (Task 4).

### Task 4: `core/operation.ts` and `core/render.ts`

**Files:**

**Interfaces:**
- Produces in `operation.ts`:
  ```ts
  export type Category = 'read' | 'create' | 'update' | 'delete' | 'action';
  export type OutputKind = 'report' | 'reports' | 'resource';
  export interface Column { header: string; path: string; format?: (v: unknown) => string }
  export interface RunContext { property: string; globals: GlobalOptions; interactive: boolean }
  export interface OperationDef<I extends z.ZodObject = z.ZodObject, O = unknown> {
    id: string;                   // dot path = CLI path, e.g. 'admin.custom-dimensions.list'
    summary: string; description?: string;
    category: Category; idempotent?: boolean;
    api?: { service: 'data' | 'admin'; version: 'v1beta' | 'v1alpha'; rpc: string };
    needsProperty?: boolean;
    kind: OutputKind;
    input: I; output: z.ZodType<O>;
    columns?: Column[];           // table/csv/chart projection for kind 'resource'
    flags?: Partial<Record<Extract<keyof z.input<I>, string>, string>>; // verbatim commander flag strings
    run(input: z.output<I>, ctx: RunContext): Promise<O>;
  }
  export function defineOperation<I extends z.ZodObject, O>(def: OperationDef<I, O>): OperationDef<I, O>;
  export const isMutating: (c: Category) => boolean; // create|update|delete|action
  export function cliPath(op: Pick<OperationDef, 'id'>): string[];
  ```
- Produces in `render.ts`: `renderResult(op: Pick<OperationDef,'kind'|'columns'>, result: unknown, opts: { format: OutputFormat; fields?: string[]; pretty: boolean }): string`. Rules:
  - **`report`** (a `ReportData`): `fields` keeps only those headers, in order. An unknown header → `GacliError('usage', 'Unknown field(s): x. Available: …')`. Formatting uses `formatOutput`, with json via `formatJson(d,{pretty})`.
  - **`reports`** (`ReportData[]`): the same field filter per report, then `formatReports`.
  - **`resource`**:
    - `items = Array.isArray(result) ? result : [result]`.
    - `fields` projects each item to `{ [path]: getPath(item,path) }`. A path that is undefined in every item, when items are non-empty → usage error.
    - **json:** `{ rowCount, data }` for arrays, `{ data }` for objects.
    - **ndjson:** one line per item.
    - **table/csv/chart:** a ReportData built from `columns`, or from `fields`, or from the first item's top-level keys.
    - Cell values: `null`/`undefined` → `''`, objects → `JSON.stringify`, otherwise `String`, or `column.format(v)`.
  - `toPlain(x)`, also exported, returns `JSON.parse(JSON.stringify(x))`. It strips protobuf class instances.

### Task 5: `core/cli-adapter.ts`: mount operations onto commander

**Files:**
- Create: `src/core/cli-adapter.ts`, `src/core/confirm.ts`
- Modify: `src/cli.ts`. It switches to `await program.parseAsync()` and calls `finalizeProgram(program)` after mounting. On a thrown `CommanderError` it exits 0 for `commander.helpDisplayed`/`commander.version`/`commander.help`, otherwise it calls `handleError(err)`.
- Test: `test/core/cli-adapter.test.ts`, which uses fake operations with no network.

**Interfaces:**
- Produces:
  - `mountOperations(program: Command, ops: OperationDef[]): void`
  - `finalizeProgram(program: Command): void`. It recursively applies `exitOverride()`, then `configureOutput({ outputError: () => {} })` so that `handleError` is the only error printer.
  - `GROUP_DESCRIPTIONS: Record<string, string>`, keyed by joined path prefix, e.g. `'admin'` or `'admin custom-dimensions'`.
  - `confirm(question: string): Promise<boolean>` in `confirm.ts`. It uses readline on stdin/stderr and treats `y`/`yes` (case-insensitive) as true.
- Mounting rules:
  - Walk/create group commands, reusing an existing child of the same name.
  - An existing leaf of the same name → throw `Error('Duplicate command path: …')` at startup.
  - Each `input.shape` key gets the flag `op.flags[key] ?? generated`. Generated flags are `--kebab <kebab>`, arrays `--kebab <kebab...>`, booleans `--kebab`.
  - The description comes from the zod `.describe()` text. A zod default is passed as the commander default.
  - A key that is neither optional nor defaulted, and not boolean → `requiredOption`.
  - Injected on every op: `--fields <paths>` (comma-separated).
  - On mutating ops: `--dry-run`.
  - On `delete`: `-y, --yes` plus a hidden `--force`.
- Execution order:
  1. `resolveGlobalOptions(command)`.
  2. If `needsProperty`, `validatePropertyId`.
  3. `op.input.parse(pick(opts, shapeKeys))`. A ZodError → exit 2 via `handleError`.
  4. `--dry-run` → `writeOutput(JSON {dryRun:true, operation:id, rpc:api?.rpc, property, input})` and stop. The API is not called.
  5. For `delete` without `--yes`/`--force`:
     - interactive → `confirm(\`${op.summary}? [y/N] \`)`, and "no" → `GacliError('confirmation','Aborted.')`;
     - non-interactive → `GacliError('confirmation', \`Refusing to run "${path}" without --yes.\`, { hint: \`Re-run: gacli ${process.argv.slice(2).join(' ')} --yes\` })`.
  6. A spinner (`createSpinner(op.summary)`) when `interactive` and the format is not json/ndjson.
  7. `result = await op.run(input, ctx)`.
  8. `renderResult(op, kind==='resource' ? toPlain(result) : result, {format, fields, pretty: !!process.stdout.isTTY})`.
  9. `writeOutput`.
  10. On any throw: stop the spinner, then `handleError`.
