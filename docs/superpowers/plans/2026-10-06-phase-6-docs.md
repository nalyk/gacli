# Phase 6 — Docs from the catalogue: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The operation reference in `help.md`, the skills command catalogue and an `llms.txt` are generated from `OPERATIONS`, and CI fails on drift. Add a 1.x → 2.0 migration guide, and refresh README, CLAUDE.md, the memories and the skill packages for 2.0.

**Architecture:**
- `scripts/gen-docs.ts` (run with tsx) imports `OPERATIONS` and `buildCatalog`. It renders Markdown into marked regions:
  - `help.md`: `<!-- BEGIN GENERATED: operations -->` … `<!-- END GENERATED: operations -->`
  - `extensions/_core/command-catalog.md`: `<!-- BEGIN GENERATED: operations-index -->` … `<!-- END GENERATED: operations-index -->`
  - writes `llms.txt` whole (`toLlmsMarkdown`)
- `pnpm docs` writes the files. `pnpm docs:check` exits 1 with a diff summary when a file is stale. A vitest test (`test/docs/generated.test.ts`) runs the same check, so `pnpm test` and CI catch drift.
- Hand-written prose stays outside the markers: global options, auth, config, explore, mcp, skills, api, filter syntax, notes.

**Spec:** §5.9, §6 row 6. Covers the phase 4 deferred doc minors (catalogue drift, README feature list).

## Global Constraints

- Branch `feat/phase-6-docs` off `next`. No AI attribution in commits.
- Generated output is deterministic: catalogue order, no timestamps, LF line endings.
- The useful 1.x prose moves into operation `description`s, so it also reaches `gacli schema` and MCP tool descriptions:
  - the report run example
  - the batch request-file format and the multi-report output note
  - the access-bindings `--parent`/`--roles` notes

## Review Focus

1. Editing an operation's flag without running `pnpm docs` must make `pnpm test` fail with a message naming `pnpm docs` (Task 1).
2. The generated `help.md` keeps every hand-written section outside the markers byte-for-byte (Task 1).
3. MIGRATION.md lists every BREAKING CHANGE footer on `next` since 1.1.0. Check with `git log --grep "BREAKING CHANGE" main..next` (Task 2).
4. Skill packages: `verify:skills` passes and `min_gacli_version` says 2.0.0 (Task 2).
5. `llms.txt` stays reasonably small. Record the size and judge it (Task 1).

### Task 1: Generator, markers, drift check

**Files:**
- Create: `scripts/gen-docs.ts`, `src/core/docs.ts`, `test/docs/generated.test.ts`, `llms.txt`
- Modify: `help.md`, `extensions/_core/command-catalog.md`, `package.json` (`docs`, `docs:check`; `verify` adds `docs:check`), some op descriptions
- `src/core/docs.ts`:
  - `renderHelpSections(catalog): string` produces one `## gacli <path>` section per operation:
    - summary
    - description paragraphs
    - a usage block
    - an options table (Flag | Required | Default | Description)
    - a line "Needs `-p <property>`." / "Destructive: requires `--yes` when not interactive." / "Supports `--dry-run`."
    - "Output: `-f json` → …" naming the envelope (report / list / single / reports)
  - `renderCatalogIndex(catalog): string` produces one table per top-level group (Command | Category | Purpose)
  - `replaceRegion(text, name, content): string` throws if the markers are missing
