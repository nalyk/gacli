# Phase 3 — MCP v2 server generated from the catalogue: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the hand-written 4-tool MCP server with one generated from `OPERATIONS`. It runs on MCP TypeScript SDK v2 (`@modelcontextprotocol/server`), supports stdio and local Streamable HTTP, and offers typed `outputSchema`/`structuredContent`, annotations and opt-in write/delete tools.

**Architecture:**
- `src/core/invoke.ts` extracts the transport-neutral part of `executeOperation`: input parse, property resolution and run.
- The CLI adapter and the MCP adapter (`src/core/mcp-adapter.ts`) both call it.
- The MCP adapter builds a server factory: one tool per operation, filtered by the allow-flags, in deterministic order.
- `gacli mcp serve` wires the factory to stdio (`StdioServerTransport`) or to HTTP (`createMcpHandler` + `toNodeHandler`, bound to 127.0.0.1, with Host and Origin validation).

**Tech Stack:** `@modelcontextprotocol/server` ^2.3.1 (supports protocol 2025-11-25 and older, verified by probe), `@modelcontextprotocol/node` ^2.1.1, zod 4. `@modelcontextprotocol/sdk` is removed.

**Spec:** §5.5, §6 row 3, success criterion 3.

## Global Constraints

- **Tool name:**
  - The rule is `ga_` + the id with `.` and `-` replaced by `_`, e.g. `ga_report_run` and `ga_admin_custom_dimensions_list`.
  - The 1.x names (`gacli_report_run`, `gacli_report_realtime`, `gacli_metadata`, `gacli_check_compatibility`) are removed. This is a BREAKING CHANGE and goes in the footer.
- **Tool input schema:** the operation's input object, extended as follows. Values arrive as JSON, so the zod coercions accept them.
  - `propertyId` (string, digits) on every `needsProperty` op. It is optional when the server was started with a default property, otherwise required.
  - `dryRun?` on every mutating op.
  - `confirm: z.literal(true)` on delete ops.
  - `fields?: string[]` on all ops.
- **outputSchema:** the `-f json` envelope from `jsonOutputSchema(op)`. For `kind: 'reports'` it is wrapped as `{ reports: [...] }`, because MCP requires an object.
- **Result:** `structuredContent` is that envelope. `content` is one `text` block holding the same envelope as compact JSON.
- **Errors:** `{ isError: true, content: [{type:'text', text: JSON.stringify(gacliError.toJSON())}] }`. A tool never throws.
- **Annotations:**
  - `read` → `readOnlyHint: true, idempotentHint: true, openWorldHint: true`.
  - `delete` → `destructiveHint: true`.
  - `create`/`update`/`action` → `readOnlyHint: false, destructiveHint: false`.
  - `title` = summary.
- **Exposure:** default read-only. `--allow-write` adds create/update/action. `--allow-delete` adds delete and implies write.
- **HTTP:**
  - `--http <port>` binds `127.0.0.1` only.
  - Requests with Host/Origin outside localhost are rejected using the SDK's `hostHeaderValidationResponse`/`originValidationResponse` with `localhostAllowedHostnames`/`localhostAllowedOrigins`.
  - No auth. Document that it is local-only.
- **stdout/stderr:** on stdio, stdout belongs to the protocol. Nothing else may write to stdout: no spinners, `writeOutput` or `console.log`.
- No AI attribution in commits.

## Review Focus

1. A tool call whose operation throws a gRPC NOT_FOUND must return `isError` with exit-code 5 JSON, and the server keeps running (Task 2).
2. A delete tool called without `confirm: true` must be rejected by schema validation, and the API must not be called (Task 2).
3. With no default property and no `propertyId`, a `needsProperty` tool returns an `isError` usage error, not a crash (Task 2).
4. The HTTP server must reject a request with `Host: evil.com` (DNS rebinding) and accept `Host: 127.0.0.1:<port>` (Task 4).
5. The `tools/list` order is identical across two server instances (Task 2).

### Task 1: `core/invoke.ts`, the transport-neutral invocation

**Files:**
- Create: `src/core/invoke.ts`
- Modify: `src/core/cli-adapter.ts` (`executeOperation` uses it)
- Test: `test/core/invoke.test.ts`

**Interfaces:**
- Produces:
  - `parseOperationInput(op, raw: Record<string, unknown>, label?: (key) => string): z.output<op.input>`. It throws a usage `GacliError` with flag- or key-named messages, the same text as the adapter today.
  - `resolveProperty(op, candidate: string | undefined): string`, which runs `validatePropertyId` when `needsProperty` and returns `''` otherwise.
  - `toEnvelope(op, result): unknown`. It produces exactly the object `renderResult(...,{format:'json'})` serialises. `renderResult` json/ndjson must be refactored to call it, so the two can never drift. For `reports`, a single report gives the envelope object and several give an array.

  - `resolveProperty` handles both needsProperty cases.
  - `toEnvelope` for report, a resource list, a single resource, and reports with 1 and 2 entries.
  - `JSON.stringify(toEnvelope(...)) === renderResult(..., {format:'json', pretty:false})` for each kind.
- [ ] Refactor the adapter and render to use it. The full suite stays green.

### Task 2: `core/mcp-adapter.ts`, the tool factory

**Files:**
- Create: `src/core/mcp-adapter.ts`
- Test: `test/core/mcp-adapter.test.ts`. It uses the SDK's `InMemoryTransport` plus a minimal JSON-RPC driver, or the SDK client if available.

**Interfaces:**
- Produces:
  - `toolName(op): string`
  - `toolInputSchema(op, opts: { defaultProperty?: string }): z.ZodObject`
  - `toolOutputSchema(op): z.ZodObject`
  - `toolAnnotations(op): ToolAnnotations`
  - `exposedOperations(ops, { allowWrite, allowDelete }): AnyOperation[]`
  - `createServerFactory(ops, opts: { version: string; defaultProperty?: string; allowWrite?: boolean; allowDelete?: boolean; globals: GlobalOptions }): () => McpServer`

  Each tool handler does the following:
  1. Strip `propertyId`, `dryRun`, `confirm` and `fields`.
  2. `resolveProperty(op, args.propertyId ?? defaultProperty)`.
  3. `parseOperationInput`.
  4. Dry run → structured `{ dryRun, operation, rpc, property, input }`.
  5. Run, `toPlain`, then `toEnvelope`, then project `fields`.
  6. Wrap a report envelope for reports.
  7. Any throw → `toGacliError` → isError result.
- [ ] Tests, using fake ops as in `test/core/cli-adapter.test.ts`:
  - The names match the rule.
  - Read-only by default; `--allow-write` exposes create/update but not delete; `--allow-delete` exposes everything.
  - The annotations match the table.
  - A `tools/call` happy path returns `structuredContent` equal to the envelope and passes `outputSchema` validation.
  - A NOT_FOUND op error gives `isError` with `exitCode` 5.
  - A delete without `confirm` is rejected (`isError` or a JSON-RPC invalid params error) and `run` is not called.
  - A missing property gives a usage isError.
  - `tools/list` is deterministic across two factory instances.
- [ ] Commit `feat(mcp): generate MCP tools from the operation catalogue`
